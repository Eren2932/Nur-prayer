# Фактические проверки 0.3.3 — 7 сентября 2026

## Причина ошибки из пользовательского отчёта

Получен публичный HEAD репозитория Eren2932/Nur-prayer; из него извлечены исходники 0.3.2
и `nur-reports (1).zip`. В отчёте предыдущей версии: **122 unit-теста, 0 failures, 0 ignored**.
Debug APK собрался. Общий run завершился ошибкой компиляции Android UI-тестов, не доказанным
runtime crash приложения. Исходный build.log сохранён в `ci-failure-0.3.2/`.

`AtlasUiTest.kt:72` и `:88`: цепочки `performTextInput(...).performImeAction()` неверны,
поскольку первый вызов возвращает Unit. Теперь сохранён объект searchField и на нём отдельно
вызываются два действия. Тесты не удалены, ожидания не ослаблены. Новая узкая статическая
проверка обнаруживает обе ошибки исходника и не обнаруживает их в исправленном файле.

## Добавлено, но здесь НЕ выполнено

Четыре новых JVM-теста QiblaGuidance доводят suite до **126** тестов. Пять новых UI-тестов
доводят androidTest до **10**. Они добавлены для проектной среды Kotlin 2.0.20 / Android,
а не исполнены через Python или отдельный устаревший Kotlin.

Новый workflow сначала компилирует debug/release и оба test source sets. Затем выполняет
unit-тесты, собирает debug/release/androidTest APK, запускает R8 и существующий advisory lint.
Отдельные задания API 26/34 запускают собранные APK с AndroidJUnitRunner; отсутствие
успешного `OK (N tests)` считается ошибкой. UI-тесты не пропускаются при отсутствии магнитометра:
их сценарии от аппаратных датчиков не зависят.

**Новая Android-сборка, JUnit, UI-исполнение, R8, lint, физические датчики, GPS, азан,
скриншоты Android и FPS не проверены в этой сессии.** Gradle/Android SDK в the Computer не настроены;
пакеты и toolchain не устанавливались. Успех 122 тестов из исходного ZIP нельзя приписывать 0.3.3.
Зелёного Actions run для 0.3.3 ещё нет. Существующий `lint.abortOnError=false` не изменён,
поэтому lint-отчёт даже при успешном CI требуется просмотреть вручную.
